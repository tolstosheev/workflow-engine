# CONTRIBUTING

Короткие правила работы над проектом. Полное описание — в
[`docs/GIT_WORKFLOW.md`](docs/GIT_WORKFLOW.md) и [`AGENTS.md`](AGENTS.md).

## Инварианты движка

Прежде чем менять код ядра, прочитай `AGENTS.md` §3. Там перечислены жёсткие
правила: журнал событий как единственный источник истины, запрет долгих
транзакций БД, lease вместо распределённых блокировок, обязательная
идемпотентность обработчиков, необратимость компенсаций. Нарушение любого из
них ломает восстановление после падения воркера.

## Ветки

```bash
git switch develop
git switch -c feature/<область>-<описание>
```

- `feature/*` и `fix/*` — от `develop`, слияние обратно в `develop` через `--no-ff`.
- `release/*` — от `develop`, сливается в `main` и `develop`, получает тег.
- `hotfix/*` — от `main`, сливается в обе ветки.
- `main` и `develop` вечные; `--force` запрещён.

## Коммиты

```
<type>(<scope>): <subject>

<body — почему, а не что>
```

- Один коммит — одна область. Области перечислены в
  [`docs/GIT_WORKFLOW.md` §2](docs/GIT_WORKFLOW.md#2-области-коммитов).
- Subject до 72 символов, строчные буквы, императив, без точки.
- Тело объясняет причину. Если причина неочевидна — тело обязательно.
- Сообщения на английском.

Пример:

```text
fix(lease): продление heartbeat не работает во время исполнения шага

Heartbeat обновлялся только между шагами, поэтому долгий шаг с внешним
вызовом успевал протухнуть по TTL, и инстанс перехватывал второй воркер.
```

## Проверки

```bash
make check   # ruff, ruff format, mypy, eslint, tsc
make test    # pytest, порог покрытия 92% (branch)
```

Красные проверки — повод чинить код, а не ослаблять правила. Понижать порог
покрытия или добавлять `# pragma: no cover` без объяснения в теле коммита
нельзя.

## Документация

- Архитектурное решение с последствиями оформляется ADR в `docs/adr/`
  (формат Nygard, раздел «Negative» обязателен).
- Схемы — Mermaid, исходники в `docs/diagrams/*.mmd`.
- Документация обновляется тем же коммитом, что и код. Смешивать код и
  документацию в одном коммите нельзя: это отдельные области.
- Всё на русском языке.

## Комментарии в коде

Комментарий объясняет **почему**, а не что. Пересказ кода — это шум, который
устаревает. Норма — примерно одна строка комментария на десять строк кода, но
только там, где причина неочевидна из самого кода.
